How access works

Every tool is a thin call into /api/agent/*. The route checks the scope on each call, so the scope map below is enforced by the server and does not depend on the agent behaving.

1 · TokenIssued by Michael

Manual tokens at /agents default to read and write, with delete off. OAuth approval mints a 365-day token and grants read, write and delete unless the client asks for fewer.

2 · Door/api/mcp checks the owner

The hosted endpoint needs gallery:read and an owner on the allowed list. Anyone else gets 401 or 403.

3 · ScopeEach route checks again

Invalid, expired or revoked: 401. Valid but short of scope: 403 naming the exact scope missing.

4 · OwnerThe token decides whose data

Tools never take an owner id. Whatever the token owns is what the agent sees.

Hosted · OAuthConnector sign-in, no token to copy. claude.ai, Claude Desktop.
Hosted · BearerSame URL with a token. Cloud sessions, CI, Codex, this repo's .mcp.json.
Local stdioserver.ts with a token. The one route that can read a local filePath.
No MCPscripts/gallery.mjs reaches the same tools by token, and adds the all_assets export.

What it cannot do

Two kinds of "cannot", and the difference matters. The left column is enforced by code. The right column is possible for a token with the scope, so only the agent's instructions hold it back.

Enforced by code

Refused, or no tool exists.

  • Reach another person's galleryThe owner comes from the token, an ownerUserId in the body is ignored, and /api/mcp returns 403 for anyone off the allowed list.
  • Delete with a read or write tokenThe nine delete tools need gallery:delete. The route answers 403 and names the missing scope.
  • Raise its own permissionsNo MCP route touches tokens. Changing scopes takes a signed-in owner session at /agents. OAuth tokens need a new consent.
  • Star, publish or like an assetNo tool does it, and update_gallery_item's backend validator refuses those fields.
  • Answer an Inbox card for MichaelThe Inbox route has post, list, decisions, close, delete and similar_groups. It has no answer action.
  • Generate media or run MidjourneyNo tool calls a model or submits a job. Moodboard and profile tools record codes only.
  • Read a local file on the hosted serverfilePath exists only on local stdio. Hosted clients send url, fileBase64 or an uploadId.
  • Edit or delete comments, or delete tasks and tagsNo such tools. Tags can only be archived.
  • Overwrite owner instructions unseenupdate_skill_instructions needs the sha256 from the read. A stale one gets 409.

Rule only

The server would allow it. Written in the skill and tool descriptions.

  • Delete without Michael's named approvalgallery:delete is technical access. The server cannot tell whether a human agreed, and no agent-supplied flag counts as consent.
  • Set a collection showcased or featuredA write token can do this and it changes the public site. Only the rule requires his publication instruction.
  • Mark work approvedupdate_character accepts status approved or sheeted from any write token. The rule says only when Michael approved it.
  • Judge taste in the InboxAgents state facts in their cards and he decides. Nothing inspects the wording.
  • Mark a new worldmark_world works with write scope. The rule says only when Michael creates one.
  • Print a tokenNothing stops an agent that holds a token from pasting it. Keep it in the environment.

Midjourney

What this release adds for agents, and where the MCP stops.

Can readThe job behind a saved image

get_gallery_item returns midjourneyMetadata: job, tile, moodboard and profile codes, settings. It exists on images saved from the extension since this release. List and search rows leave it out to stay slim.

Cannot writeThat metadata

save_asset and update_gallery_item have no such field. Only the extension's save route writes it.

Cannot reachThe copy list

It lives in Chrome's extension storage. No tool reads it. Michael pastes it to the agent, and nothing on it is in the gallery until someone saves it.
