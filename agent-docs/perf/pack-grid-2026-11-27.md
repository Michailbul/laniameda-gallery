# Mobile gallery loading

Against main at `fb0d844`, four visible image packs loaded **2.74× faster**. Tapping an uncached frame made that picture ready **2.37× faster**.

| Cold mobile grid, median of three | Before | After |
| --- | ---: | ---: |
| First image request until all 12 displayed or stacked stills decoded | 2,798 ms | 1,020 ms |
| Tap on the fourth frame until its active image decoded | 696 ms | 294 ms |
| Encoded image bytes for the same 12 stills | 530,920 | 168,064 |

The browser rendered the gallery’s masonry grid and pack cards. Each pack contained six square frames made from the checked-in world artwork, with the gallery’s thumbnail sizes and WebP qualities. Chromium used a fresh context per run, a 390 × 844 viewport at 2× density, 1.6 Mbps download and 80 ms latency. Reduced motion held the rotation still until the tap. Timings start at the first image request or tap and exclude login and database latency.

The initial decode times in milliseconds were 2,805 / 2,798 / 2,791 before and 1,020 / 1,016 / 1,029 after. The tap times were 696 / 701 / 683 before and 292 / 296 / 294 after. To repeat, run a production build in each checkout, copy both benchmark files into the baseline checkout, and run `bun agent-docs/perf/tools/pack-grid.mjs` in each. Set `CHROME_PATH` to use a system Chromium.

## Dashboard and route checks
